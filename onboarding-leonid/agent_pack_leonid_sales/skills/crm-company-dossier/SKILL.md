# CRM Company Dossier (pre-touch)

Цель: до первого касания собрать **персонализированное досье** и **3 захода** первого сообщения, бьющих в актуальную боль — не generic «мы делаем видео».

Стык с архитектурой: [artifact_crm_outreach_b2b_conversion_system_2026.md](../../../40_Artifacts/artifact_crm_outreach_b2b_conversion_system_2026.md) (Contour A).
Стык с контактами: [crm-contact-factcheck](../crm-contact-factcheck/SKILL.md) = сфера/должность/URL; **этот skill** = бизнес-контекст и копирайт захода.

## Когда применять

- «досье на компанию X», «ресёрч перед письмом», «заходы для cold»
- Перед запуском касания в Contour A (TGND / Sputnik outreach)
- `call-prep` для клиента/лида, если досье ещё нет
- Батч по очереди: топ из `build_crm_research_queue.py` (не все 500 сразу)

## Не делать

- Не подключать Clay / Apollo как обязательный шаг (RU MVP).
- Не выдумывать новости, ФИО ЛПР, бюджеты без источника.
- Не писать ПД (телефоны, личные email) в git — только публичные факты + ссылки.
- Не класть сырые выгрузки Export-Base / Контур в репо.

## Workflow

### 1. Вход

Нужно минимум: **название компании** и желательно **сайт**. Опционально: отрасль, желаемый ЛПР (маркетинг / закупки / бренд), deal_id / project folder.

### 2. Ресёрч (открытые источники)

Порядок:

1. Официальный сайт / «о компании» / продукты / кейсы
2. Новости 6 мес: релизы, запуски, тендеры (поиск `[компания] 2026`, отраслевые СМИ)
3. Найм / вакансии (сигнал роста / новых функций)
4. Rusprofile / Checko — юрлицо, гендир (для МСБ часто = ЛПР), смежные ООО
5. LinkedIn / карьерные страницы — гипотезы ЛПР (маркетинг, бренд, digital, закупки)
6. При наличии карточки в CRM / Amo safe index — сверить, не противоречить factcheck

### 3. Канон-промпт (ядро анализа)

Адаптировать под ICP видеопродакшна / док / бренд longform (Sputnik / Cult):

```
Собери досье на компанию [название, сайт]. Мне нужна информация о том,
чем занимаются и на чём зарабатывают, что происходило у них за последние
полгода (новости, запуски, найм), кто отвечает за [маркетинг / бренд /
закупки контента], какие боли у них могут быть в [видеопродакшн /
документалистика / брендовый longform / employer brand / сезонная
кампания]. В конце предложи три захода для первого письма, привязанных
к их ситуации. Каждый факт с источником (URL). Не выдумывай.
```

### 4. Выходной файл

Путь (приоритет):

1. `20_Business_Projects/sputnik_films/leads_opportunities/<slug>/note_company_dossier_<slug>_YYYY_MM_DD.md`
2. Если есть папка клиента/проекта — туда же
3. Для Cult/других проектов — зеркально в их `leads_opportunities/` или project folder

Имя: snake_case, `type_first`. Создать `README.md` в новой папке клиента, если папки ещё нет.

Шаблон тела:

```markdown
# Досье: [Компания]

Файл: `note_company_dossier_...`
Тип: Note
Дата: YYYY-MM-DD
Связь CRM: deal_id / карточка (если есть)

## Чем занимаются / на чём зарабатывают
...

## Сигналы за ~6 месяцев
- Новости / запуски (URL)
- Найм (URL)

## ЛПР / стейкхолдеры (гипотезы)
| Роль | Кто / уровень уверенности | Источник |

## Боли под наш оффер (гипотезы)
- ...

## ICP fit (черновик)
- Класс A/B/C (черновик) + 1–2 причины
- Anti-ICP red flags (если есть)

## Три захода первого касания
1. **Угол:** …
   **Черновик 2–4 предложения:** …
2. …
3. …

## Источники
- url — что взяли
```

В чате — краткая выжимка + путь к файлу. В карточку CRM (если сделка уже есть) — одна строка в примечание / next touch: «досье YYYY-MM-DD → path» (только с ок пользователя, если правка leads MD).

### 5. Стык с call-prep и outreach

- После досье: пользователь может скопировать заход в шаблон TGND / Sputnik.
- `call-prep` читает готовое досье (саммари, не весь веб заново).
- Батч: после factcheck по контактам — dossier только на Tier A / высокий priority.

## Handoff

- Должность/сфера контакта без бизнес-нарратива → `crm-contact-factcheck`
- Скоринг сделки CoT A/B/C → role `sales-newbiz`
- Код автоматизации рассылки → vibecoder
