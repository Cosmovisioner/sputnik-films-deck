# Call Prep (автоматическая подготовка к созвону)

## Принцип

Агент **сам** собирает повестку из всего доступного контекста. Пользователь получает готовый документ «иди на созвон с этим». Никакого ручного сбора.

## Входные данные

Агент определяет участника из:
- Прямого запроса: «подготовь к созвону с Денисом»
- Журнала дня: ближайшее событие с именем
- Календаря (если синхронизирован)

## Workflow

### 1. Идентифицировать участника и контекст

- Найти имя в запросе или в расписании дня.
- Определить проект / зону (Cult Group, Sputnik, ТГНД, личное).

### 2. Собрать источники (параллельно)

| Источник | Что искать |
|----------|------------|
| Предыдущие саммари встреч (`meetings/`) | Последний созвон с этим человеком: решения, action items, открытые вопросы |
| CRM (`artifact_crm_leads_2026.md`) | Если клиент — статус сделки, последнее касание |
| Company dossier (`note_company_dossier_*`) | Pre-touch досье: боли, сигналы, заходы — в `leads_opportunities/` или папке клиента |
| Журнал задач | Задачи, связанные с этим человеком / проектом |
| Inbox задач | Незакрытые вопросы к этому человеку |
| Операционные файлы проекта | Актуальные артефакты (правила, вакансии, документы) |

**Хук dossier:** если созвон с клиентом / лидом / cold→warm и файла `note_company_dossier_*` нет — сначала выполнить skill [crm-company-dossier](../crm-company-dossier/SKILL.md) (хотя бы сжатое досье в чат), затем собрать повестку. Не перечитывать весь веб, если досье уже свежее (< 30 дней).

### 3. Сформировать брифинг

Формат:

```
СОЗВОН: [Имя] — [дата, время]
КОНТЕКСТ: [одна строка — зачем созвон]

НЕЗАКРЫТОЕ С ПРОШЛОГО РАЗА:
• [action item — статус]
• [открытый вопрос]

ПОВЕСТКА (предложение):
1. [тема] — цель: [что нужно получить]
2. [тема] — цель: [что нужно получить]
3. [тема] — цель: [что нужно получить]

ПОДГОТОВИТЬ / ПОКАЗАТЬ:
• [файл / ссылка / цифра — если нужно иметь под рукой]

ЧЕГО НЕ ОБСУЖДАТЬ (если есть ограничения):
• [тема — почему нет]
```

### 4. Правила

- **Макс 3–5 пунктов повестки** — созвон не резиновый.
- **Цель у каждого пункта** — не «обсудить», а «получить ок / решение / дату».
- **Чувствительные темы** — проверить карточку контакта (если есть) на ограничения.
- **Не грузить** пользователю весь контекст — только выжимку и предложение.
- **Тон** — деловой, без воды, сканируется за 20 сек.

### 5. После вывода

- Пользователь правит / добавляет → агент обновляет.
- Если пользователь говорит «ок» — повестку можно скинуть участнику (предложить).
- После созвона → триггер на `meeting-report-prod` или заметку.

## Автоматический триггер (без запроса)

При выполнении `day-start`: если в расписании есть созвон через < 2 часов — автоматически добавить в брифинг дня блок «Подготовка к [имя]» со сжатой версией повестки (3 пункта).

## Не делать

- Не читать полные транскрипты прошлых встреч (только саммари).
- Не предлагать повестку для рутинных 1:1, если нет незакрытых action items (просто сказать «повестки нет — catch-up»).
- Не дублировать повестку в файл без запроса (только в чат).
